## 结果记录

每次验收写明版本（commit）、日期、设备 / 浏览器、前置条件、输入、预期、实际结果、证据与结论。未执行的用例保持“未执行”；不要以设计预期代替实际结果。

建议指标：核心任务通过数 / 已执行核心任务数、异常用例通过数 / 已执行异常用例数、修复后通过数 / 已回归失败用例数。记录分子和分母；没有样本时记为 N/A，不给出虚构通过率。

## Case 与失败归因

- **Good Case：** 实际达到验收标准，保留输入与证据作为回归基线。
- **Bad Case：** 实际结果偏离预期，记录复现条件、影响和根因。
- **Boundary Case：** 空数据、重复操作、极端输入、跨日或依赖故障等边界条件。

归因可选择：需求定义、数据内容、业务规则、交互状态、存储、外部依赖、构建发布。模型 / Prompt 仅用于真实涉及模型调用的场景。

## 迭代步骤

1. 执行核心流程与异常用例，保存证据。
2. 对失败按影响排序，先修复阻断核心任务或损坏数据的问题。
3. 保留原始输入，记录修改前后的实际差异。
4. 用同一版本环境回归失败用例，并复查相邻核心流程。
5. 更新状态和版本记录；未验证的能力继续标注为待验证。
